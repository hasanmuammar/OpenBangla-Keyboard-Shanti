= Shanti Keyboard

**Shanti — Highly Experimental, Vibe-Coded Fork of OpenBangla Keyboard for Modern Linux Operating Systems, including Bazzite, Bluefin and similar atomic/image-based systems.**


### ⚠️ HIGHLY EXPERIMENTAL FORK

This repository is **Shanti Keyboard**, a **Linux-focused fork of OpenBangla Keyboard created to make it easy to install on modern Linux operating systems such as Bazzite and Bluefin**. It keeps the OpenBangla Keyboard codebase while adding a simpler prebuilt installation and runtime-bundling workflow for conventional Linux systems and modern atomic/image-based systems.

The main purpose of this fork is to make a Bangla keyboard practical on modern Linux operating systems such as Bazzite and Bluefin, using user-local installation and bundled runtime libraries. Source building and release packaging are available through `tools/build.sh`.

Shanti Keyboard is an open-source, Unicode-compliant **Bangla (Bengali) keyboard and input method for Linux**. It provides phonetic and fixed keyboard layouts, typing automation, dictionary support and autocorrection.

[WARNING]
====

== What this fork provides

* **Prebuilt Linux releases** for x86_64 and ARM64.
* **Flatpak packages for both input-method stacks:** GNOME uses IBus (`org.shanti.ShantiIbus`); Fcitx5-based desktops use the Fcitx5 addon (`org.fcitx.Fcitx5.Addon.Shanti`).
* **Automatic backend selection for source/portable installs:** KDE Plasma uses Fcitx5; other desktop environments use IBus.
* **User-local installation** under `~/.local` without a system-wide package install.
* **Source builds** remain available through `tools/build.sh`.
* **Isolated source builds** using Toolbx, Distrobox, Podman, or Docker.
* **Bundled Qt5 and required runtime libraries** for the user-local installation.
* **Automatic IBus component registration** for user-local installations.
* **User-local uninstaller** with optional cache removal.
* **Legacy-safe upgrades:** installs from pre-rebrand releases (openbangla-keyboard paths, `org.openbangla.Shanti.IBus`) are migrated automatically to the new Shanti names on first run.

== Bangla keyboard and input-method features

The Shanti Keyboard codebase is built for Bangla typing on Linux and includes:

* Phonetic Bangla typing, including Avro-style phonetic input.
* Fixed Bangla keyboard layouts.
* Unicode-compliant Bengali text input.
* Typing automation for fixed layouts.
* Dictionary-based suggestions and autocorrection.
* A Qt-based configuration interface (`shanti-gui`).
* Linux desktop integration through IBus or Fcitx5.

=== Flatpak (recommended; pick one for your desktop)

Both Flatpaks are architecture-specific bundles on the link:https://github.com/hasanmuammar/OpenBangla-Keyboard-Shanti/releases[GitHub Releases] page. Which one fits:

* **GNOME** (Ubuntu, Fedora Workstation, atomic/image-based systems running GNOME): the IBus package `shanti-ibus-x86_64.flatpak` (or aarch64), Flatpak ID `org.shanti.ShantiIbus`.
* **KDE Plasma / Kinoite, or any desktop where you use Fcitx5**: the Fcitx5 addon `shanti-fcitx-addon-x86_64.flatpak` (or aarch64), Flatpak ID `org.fcitx.Fcitx5.Addon.Shanti`. Install it together with Flathub's sandboxed Fcitx5 (`flatpak install --user flathub org.fcitx.Fcitx5`) — no host Fcitx5 required.

The IBus package needs the Flathub runtime `org.kde.Platform//5.15-25.08` in the same install scope; Flatpak normally downloads it during installation. See the link:tools/flatpak/README.md[Flatpak guide] for per-desktop commands and setup.

=== Prebuilt installation

The installer downloads the configured Shanti release, verifies its checksum, and installs it for the current user. See the link:https://github.com/hasanmuammar/OpenBangla-Keyboard-Shanti/releases[GitHub Releases] page for available versions.

Supported architectures:

* x86_64
* ARM64 (aarch64)

KDE Plasma automatically uses Fcitx5. Other desktop environments automatically use IBus.

From a source checkout, install with `bash tools/install.sh`. The default release tag is in `release-tag.txt`; use `bash tools/install.sh --version TAG` to choose another release. The CMake project version is tracked separately in `version.txt`.

=== Build from source

For development, local compilation, or release packaging, use the separate source-build script:

[source,bash]
----
bash tools/build.sh
----

The source build can use Toolbx, Distrobox, Podman, or Docker to keep build dependencies out of the host system. Release packages are produced for both x86_64 and ARM64 by GitHub Actions.

[source,bash]
----
bash tools/build.sh --backend ibus --package
bash tools/build.sh --backend fcitx --package
----

=== Automated build and package testing

GitHub Actions currently tests source builds across:

* x86_64 with GCC and Clang.
* x86_64 with IBus and Fcitx5.
* ARM64 (aarch64) with GCC.
* ARM64 (aarch64) with IBus and Fcitx5.

A separate prebuilt-package test workflow builds release archives for x86_64 and ARM64 with both IBus and Fcitx5, verifies their SHA-256 checksums, inspects the archive contents, checks the bundled runtime and backend metadata, and runs `shanti-gui --version` plus `shanti-gui --check-data`. The data check verifies that layout and dictionary files can be found relative to the installed executable, not the CI builder's home directory.

The installer checks that the required data files are present. You can repeat the check with `~/.local/bin/shanti-gui --check-data`. CI validates builds and package contents; it does not replace testing Bangla input on your desktop.

== Uninstallation

Remove the current-user prebuilt installation (it cleans both the current Shanti names and the legacy pre-rebrand names):

[source,bash]
----
bash tools/uninstall.sh
----

To remove the build and staging cache as well:

[source,bash]
----
bash tools/uninstall.sh --purge-cache
----

Flatpak removal commands for both packages are in the link:tools/flatpak/README.md[Flatpak guide].

== Manual Linux build

The CMake project supports one input-method backend per build. For the normal source-build workflow, prefer `tools/build.sh` so build isolation, cache handling and packaging remain consistent. The manual commands below are for developers who specifically need to configure CMake directly.

=== IBus

[source,bash]
----
cmake -S . -B build -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_INSTALL_PREFIX="$HOME/.local" \
  -DENABLE_IBUS=ON \
  -DENABLE_FCITX=OFF

cmake --build build --parallel 2
cmake --install build
----

=== Fcitx5

[source,bash]
----
cmake -S . -B build -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_INSTALL_PREFIX="$HOME/.local" \
  -DENABLE_IBUS=OFF \
  -DENABLE_FCITX=ON

cmake --build build --parallel 2
cmake --install build
----

Pass `-DBUILD_FRONTEND=OFF` to skip the Qt5 settings GUI — this is how the Fcitx5 Flatpak addon builds, since the Fcitx5 runtime has no Qt5.

The build requires Qt5, CMake, Ninja, a C/C++ compiler, Rust/Cargo, zstd development files, and the development files for the selected input-method backend.

== Development

The project is developed on the `develop` branch.

For normal use, `tools/install.sh` downloads a prebuilt release. For source development and local compilation, use `tools/build.sh`.

[source,bash]
----
git pull --recurse-submodules
bash tools/build.sh
----

For a clean automated rebuild:

[source,bash]
----
rm -rf "$XDG_CACHE_HOME/shanti-keyboard/build"
----

If `XDG_CACHE_HOME` is not set:

[source,bash]
----
rm -rf "$HOME/.cache/shanti-keyboard/build"
----

Project-specific documentation is kept under `docs/wiki/`.

== Project structure

[cols="1,3"]
|===
|Path |Purpose

|`tools/install.sh`
|Prebuilt Linux installer; selects IBus or Fcitx5 and x86_64 or ARM64 automatically.

|`tools/build.sh`
|Source-build and release-packaging entry point.

|`tools/uninstall.sh`
|User-local uninstaller.

|`.github/workflows/package-test.yml`
|Automated prebuilt-package build and archive validation.

|`tools/portable/`
|Backend selection, isolated build, runtime bundling and installation logic.

|`tools/flatpak/`
|Flatpak manifests (IBus app + Fcitx5 addon) and the user guide.

|`crates/`
|The Rust core: settings store reader, path discovery, and the engine state machine shared by both input-method backends.

|`src/engine/ibus/`
|IBus backend (`ibus-engine-shanti`).

|`src/engine/fcitx/`
|Fcitx5 backend (`shanti` addon).

|`src/frontend/`
|Qt GUI (`shanti-gui`).

|`src/engine/riti/`
|Riti input engine submodule.
|===
