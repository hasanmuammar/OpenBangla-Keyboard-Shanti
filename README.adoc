**Shanti — Highly Experimental, Vibe-Coded Fork of OpenBangla Keyboard for Modern Linux Operating Systems, including Bazzite, Bluefin and similar atomic/image-based systems.**

This repository is a **Linux-focused fork of OpenBangla Keyboard created to make OpenBangla easy to install on modern Linux operating systems such as Bazzite and Bluefin**. It keeps the OpenBangla Keyboard codebase while adding a simpler prebuilt installation and runtime-bundling workflow for conventional Linux systems and modern atomic/image-based systems.

The main purpose of this fork is to provide **easy installation on modern Linux operating systems such as Bazzite and Bluefin**, using prebuilt Linux releases, bundled runtime libraries, and a user-local installer. Normal users do not need to set up a compiler, CMake, Rust, Qt development packages, or a build container. Source building remains available for development and release packaging.

OpenBangla Keyboard is an open-source, Unicode-compliant **Bangla (Bengali) keyboard and input method for Linux**. It provides phonetic and fixed keyboard layouts, typing automation, dictionary support and autocorrection.

== What this fork provides

* **Prebuilt Linux releases** for x86_64 and ARM64.
* **Automatic backend selection:** KDE Plasma uses Fcitx5; other desktop environments use IBus.
* **User-local installation** under `~/.local` without a system-wide package install.
* **Source builds** remain available through `tools/build.sh`.
* **Isolated source builds** using Toolbx, Distrobox, Podman, or Docker.
* **Bundled Qt5 and required runtime libraries** for the user-local installation.
* **Automatic IBus component registration** for user-local installations.
* **User-local uninstaller** with optional cache removal.

== Bangla keyboard and input-method features

The OpenBangla Keyboard codebase is built for Bangla typing on Linux and includes:

* Phonetic Bangla typing, including Avro-style phonetic input.
* Fixed Bangla keyboard layouts.
* Unicode-compliant Bengali text input.
* Typing automation for fixed layouts.
* Dictionary-based suggestions and autocorrection.
* A Qt-based configuration interface.
* Linux desktop integration through IBus or Fcitx5.

=== Prebuilt installation

Normal users do not need a compiler, CMake, Rust, Qt development packages, or a build container. The installer downloads the matching prebuilt Linux release for the current architecture and desktop environment, verifies its checksum, and installs it for the current user.

Supported architectures:

* x86_64
* ARM64 (aarch64)

KDE Plasma automatically uses Fcitx5. Other desktop environments automatically use IBus.

Install:

[source,bash]
----
git clone https://github.com/hasanmuammar/OpenBangla-Keyboard-Shanti.git
cd OpenBangla-Keyboard-Shanti
bash tools/install.sh
----

This fork does not follow the upstream OpenBangla release cycle. Alpha builds are fork-specific and use tags such as `shanti-alpha.1`. The CMake project version is kept separately in `version.txt`, while the default installer follows the release tag in `release-tag.txt`; `--version` can override it.

To install a specific alpha build:

[source,bash]
----
bash tools/install.sh --version shanti-alpha.1
----

=== Experimental Flatpak

An experimental Flatpak build is available as `io.github.hasanmuammar.Shanti` (OpenBangla Keyboard Shanti). Its GUI, AppIndicator, layout changes and settings changes have been confirmed on Bluefin/GNOME. Hosted repository publishing is not configured yet, so this is currently a developer-built package rather than a published install option. See the link:tools/flatpak/README.md[Flatpak build and publishing guide] for instructions and status.

=== Build from source

For development, local compilation, or release packaging, use the separate source-build script:

[source,bash]
----
bash tools/build.sh
----

The source build can use Toolbx, Distrobox, Podman, or Docker to keep build dependencies out of the host system. Release packages are produced for both x86_64 and ARM64 by GitHub Actions.

[source,bash]
----
bash tools/build.sh --backend ibus --package
bash tools/build.sh --backend fcitx --package
----

=== Automated build and package testing

GitHub Actions currently tests source builds across:

* x86_64 with GCC and Clang.
* x86_64 with IBus and Fcitx5.
* ARM64 (aarch64) with GCC.
* ARM64 (aarch64) with IBus and Fcitx5.

A separate prebuilt-package test workflow builds release archives for x86_64 and ARM64 with both IBus and Fcitx5, verifies their SHA-256 checksums, inspects the archive contents, checks the bundled runtime and backend metadata, and runs `openbangla-gui --version` plus `openbangla-gui --check-data`. The data check verifies that layout and dictionary files can be found relative to the installed executable, not the CI builder's home directory.

After installation, `bash tools/install.sh` also runs the data-file check. You can repeat it with `~/.local/bin/openbangla-gui --check-data`. These workflows validate the build and package structure. They do not replace functional testing of actual Bangla input on a user’s desktop.

== Uninstallation

Remove the current-user prebuilt installation:

[source,bash]
----
bash tools/uninstall.sh
----

To remove the build and staging cache as well:

[source,bash]
----
bash tools/uninstall.sh --purge-cache
----

== Manual Linux build

The CMake project supports one input-method backend per build.

=== IBus

[source,bash]
----
cmake -S . -B build -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_INSTALL_PREFIX="$HOME/.local" \
  -DENABLE_IBUS=ON \
  -DENABLE_FCITX=OFF

cmake --build build --parallel 2
cmake --install build
----

=== Fcitx5

[source,bash]
----
cmake -S . -B build -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_INSTALL_PREFIX="$HOME/.local" \
  -DENABLE_IBUS=OFF \
  -DENABLE_FCITX=ON

cmake --build build --parallel 2
cmake --install build
----

The build requires Qt5, CMake, Ninja, a C/C++ compiler, Rust/Cargo, zstd development files, and the development files for the selected input-method backend.

== Development

The project is developed on the `develop` branch.

For normal use, `tools/install.sh` downloads a prebuilt release. For source development and local compilation, use `tools/build.sh`.

[source,bash]
----
git pull --recurse-submodules
bash tools/build.sh
----

For a clean automated rebuild:

[source,bash]
----
rm -rf "$XDG_CACHE_HOME/openbangla-keyboard/build"
----

If `XDG_CACHE_HOME` is not set:

[source,bash]
----
rm -rf "$HOME/.cache/openbangla-keyboard/build"
----

Project-specific documentation is kept under `docs/wiki/`.
